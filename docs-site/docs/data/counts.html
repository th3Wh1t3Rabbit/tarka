Calls, records, and what you see in the game

Quantity What it counts
101 Retained request entries in the Euler research catalog
227 Compiled records and research concepts linked by this snapshot
98 Transfer-oriented records exposed in the Euler browser
0 Nansen provider calls issued by ordinary browser play

The 98-record collection contains 95 selected transfer-event views and three separately checked case-transaction references. The broader compilation also includes address activity, relationship summaries, source comparisons, and bounded queries with no matches.

A request is not a transfer

One response may supply several records. Different bounded questions can produce overlapping views. A counterparty response can contribute a relationship summary rather than another transfer row. A coverage check can be useful without adding a new movement to the game.

The 101-entry inventory comprises 65 token-transfer requests, 26 address-transaction requests, and 10 counterparty requests. Seventy entries are associated with reviewed research evidence; 31 remain retained request entries rather than newly admitted gameplay evidence. These classifications do not imply 101 distinct transactions or a complete reconstruction of every original execution field.

Browse the request catalog or inspect the compiled register.

The optional token snapshot is separate

The BRCG side investigation uses a separate market snapshot. Retained evidence currently binds three later BRCG requests individually and one Euler-window BRCG control. It does not contain the complete per-request audit for the separately reported 13-request collection. No combined project-request total is published, and these receipts are not silently added to the 101-entry Euler catalog.

Wider account activity

The official help article and campaign page currently publish different numeric thresholds. Evidence preparation therefore uses the stricter 1,000-request standard, while public wording remains threshold-neutral: “The eligible-window account activity exceeded the published call requirement” only after a bounded account record proves it.

The game’s documented research and account-wide activity answer different questions. Credit consumption is not a request count. Activity from each project must retain its own classification even if an account-level total is ultimately used. Eligibility evidence must come from a September 14–27 account record with a stated source and de-duplication method—not from an estimate or the number of pages in this catalog.

No account-wide request total is published here because the bounded account record and de-duplication evidence are not part of the public release. The 101 request pages and 227 compiled records describe this project library only; they are not presented as an account-eligibility total.
